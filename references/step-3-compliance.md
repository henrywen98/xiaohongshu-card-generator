# Step 3 — 违禁词合规检查

小红书对极限词 / 医疗 / 站外引流 / 平台敏感词会**限流甚至下架**。在截图**前**过一遍词库，
按建议自然替换——保持原文语气和意思不变。

```bash
node {skill-root}/scripts/check_banned_words.js ./out/xhs_long_*.html
```

## 脚本做什么

按 `data/banned-words.json` 词库扫所有 HTML 里的**可见文字**（自动剥离 HTML 标签 / CSS /
JS，不会被 CSS 里的字符串误命中）。命中词分四类：

| 图标 | 风险 | 类别 | 你要做的 |
|------|------|------|---------|
| 🔴 | **高** | 广告法极限词 / 医疗 / 站外引流 | **几乎必改**——这些是平台重点打击的 |
| 🟡 | 中 | 平台敏感 / 标题党夸张 | 结合语境判断 |
| 🟢 | 低 | 多为误报参考 | 一般可跳过 |

脚本**不自动改写**——它只给出"建议替换"，由你结合上下文判断。中文子串匹配误报很多
（"最近"含"最"、"公众号"含"号"……无害就直接跳过）。

## 你要做的（5 步）

1. 跑上面的命令
2. **逐条看命中项**，先判断是不是误报
3. 对真实违禁词，参考脚本的 `→ 建议：` 做**自然替换**
4. 改完 HTML **重新跑脚本**，直到无高风险命中
5. **记录改了哪些词**——最后给用户出《合规报告》

## 替换原则

| 场景 | 套路 | 例子 |
|------|------|------|
| 极限词软化 | 改主观 / 改语气 | 「最好」→「个人很推荐」、「第一」→「数一数二」、「100% 有效」→「亲测有效」 |
| 功效改体感 | 不说"治"，说"用起来怎样" | 「治疗痘痘」→「改善痘痘」、「美白」→「提亮肤色」、「减肥」→「身材管理」 |
| 导流转站内 | 把"加微信"变成"看主页" | 「加微信」→「看主页」、「官网」→「品牌主页」、「点击链接」→「见简介」 |
| 拿不准 | **保守改** | 高风险词宁可改；标题、正文、标签都要查 |

## 高级开关

- 加 `--json`：输出结构化结果（便于程序处理）
- 加 `--strict`：若仍有高风险命中，退出码为 1（适合放进 CI / 卡流程）

## 跑通了再走

只有 **0 个高风险命中** 才进 Step 4 出图。中风险和低风险命中的，如果脚本给的建议和你
的语气冲突，**宁可保留原文、别硬改**（中文这种损失口吻比"踩线"还糟）。
