# Step 5 — 自检 + 交付

`screenshot.js` 的缺字形检测只覆盖"字符有没有变成方块"，其它要靠你的眼睛。

## 自检清单

- **字体是否正常**：中文没有变豆腐块 / 回落成黑体；emoji 是彩色的（而不是方块 □）
- **内容是否被裁切**：固定 1440px 高 + `overflow:hidden`，文字过多会被裁——若有：
  - 调小 `--chars` 重分页（让每页字数更少、字体更不挤）
  - 或回头改 `article.txt`（砍内容 / 拆小节）
- **对齐与留白**：标题 / 正文对齐；段间距均衡；没有元素挤压或溢出
- **首页大标题**：完整显示、没有溢出 / 被色条压住
- **页码**：每页底部 `N / Total` 位置正常

## 发现问题怎么回

| 问题 | 回哪一步 |
|------|---------|
| 字体 / emoji 问题 | 看 `references/fonts.md` |
| 文字内容 / 小标题不对 | 改 `article.txt`，从 **Step 2** 重跑 |
| 违禁词 | 改 HTML，从 **Step 3** 重跑 |
| 单纯版式（想每页字数更紧 / 更松） | 调 `--chars`，从 **Step 2** 重跑 |
| 标题不满意 | 重跑 `longform_to_html.js` 传新标题 |

> 改完任何上游文件，**都要重跑 Step 3 + Step 4**——它们依赖最新的 HTML。

## 给用户交付

按这个顺序汇报：

1. **N 张 PNG** 的完整路径列表（按 `xhs_long_01.png` … `xhs_long_NN.png` 顺序——这就是
   小红书的阅读顺序）
2. **合规报告**：
   - 命中了哪些高风险词 → 替换成了什么
   - 误报跳过了哪些（简述理由）
   - 或直接写"全部通过"
3. **使用指引**：
   - 把 PNG 按文件名顺序上传小红书（小红书支持一次最多 18 张图，刚好够一篇长图文）
   - **不用再单独写文案**——mode A 的精髓是"原文成图"，标题和正文已经在图里了
   - 小红书的图片描述（alt text）可以抄 `article.txt` 的前两句

## 常见后续需求

- 用户嫌"图片多 / 图片少" → 调 `--chars` 重出图
- 用户要"再加一张结尾金句图" → 模式 A 是"原文成图"不能加，可以改成在 `article.txt` 末尾
  加一段"金句"作为正文，重跑
- 用户要"再生成一份深色版" → 当前是固定暖色版式，不支持；要换版式请直接改 `longform_to_html.js`
  里的 CSS 变量（见 `references/styles.md`）
